TDS refund checker — finding money in unused challans

Reads every TDS challan for a deductor from the income-tax portal, then confirms in TRACES how much of each remains unclaimed. What comes out is a per-TAN Excel file and a number worth reclaiming.

What is real here

  • Every line of console output — taken from the source
  • The two-phase design, e-portal then TRACES
  • Driving real Chrome because the portal blocks automation
  • The per-TAN output filenames

What is invented

  • The TAN, all challan numbers, dates and amounts
  • The BSR code
  • Every total shown

Automation limitThe portal blocks automated browsers, so it drives a real one. A person logs in with TAN, password and OTP; the tool takes over from the dashboard. Pretending this can be fully automated is how you end up with something that silently stops working.
Two portals, two phasesThe challan list and the pending balance live in different systems. Phase 1 reads the e-portal. Phase 2 confirms in TRACES what is actually still claimable. Splitting them means a failure in the second does not cost you the first.

OutputOne file per TAN, named for it. challans_AAAA00019A.xlsx. Twenty-seven runs produce twenty-seven files instead of overwriting one — a small decision that stops a long afternoon being wasted.

Reading this honestly

  • This is a reconstruction of two terminal sessions. The real tool needs Python, real Chrome and live logins to two government portals.
  • Five challans are shown; the interesting ones are the three with a pending balance.
  • Phase 2 is built — the README claiming otherwise is stale.
Why the repository is private. The code itself is private — it was built in a finance role and belongs to that context, so it is not published openly. Access can be granted on request for anyone assessing the work.
