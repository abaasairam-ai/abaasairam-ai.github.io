Invoice extractor — PDF in, checked Excel out

Reads vendor purchase invoices as PDFs and produces an Excel file ready for import, with the fields that matter pulled out and validated first. Runs fully offline and talks to nothing.

What is real here

  • The extracted fields and the Excel column layout
  • Every check code shown — these are lifted from the source
  • The GST rate validation and the GSTIN checksum test
  • The nothing-until-Export behaviour

What is invented

  • All invoice numbers, dates, amounts and vendor references
  • The GSTINs — dummies built to pass the app's own validator
  • The counts in the stat strip

ValidationThe rate check is the reason this exists. Tax divided by taxable must land on 0, 5, 12, 18 or 28 per cent. A mis-keyed rate would otherwise flow into a return unnoticed. A one-rupee rounding difference is tolerated deliberately.

ChecksumGSTINs are verified, not just pattern-matched. The last character is a check digit over the preceding fourteen. The failing row on the previous screen is the right shape and still invalid — exactly the error a regular expression waves through.

Reading this honestly

  • This is a reconstruction. The real tool is a Python application that also ships as a Windows executable needing nothing installed.
  • The six rows show a clean read plus the three failure classes worth catching.
  • The check codes are from the source, not invented for the demo.
Why the repository is private. The code itself is private — it was built in a finance role and belongs to that context, so it is not published openly. Access can be granted on request for anyone assessing the work.
