Billing API — import preview, request log, schema history

The backend behind subscription lifecycle, invoicing and client data. Three screens: a bulk import that previews before committing, a request log where an unauthorised call is refused, and the migration history.

What is real here

  • The endpoint shapes, /v1 versioning and response codes
  • Money serialised as a string to preserve precision
  • Deny-by-default authorisation — the 403 is intended
  • The migration names, which are the real ones

What is invented

  • Every client name, plan and amount
  • Row counts and rejection reasons
  • The client identifier in the DELETE call
  • All timestamps

AuthorisationThe 403 is the design, not a bug. The guard refuses unless a rule permits, rather than permitting unless a rule refuses. Adding an endpoint without a rule makes it inaccessible — which is the failure you want.
EvidenceThe migration names are the argument. A system that grew under real use leaves a trail. These are not migration_01 through migration_12.
