TDS Receivable reconciliation — three-input allocation

One screen from a four-module reconciliation suite. It takes the books ledger, a contacts export and the Form 26AS download, works out which deductor each entry belongs to, and allocates entries to 26AS rows per TAN. This demo exists so the interface and the logic can be looked at without exposing the data the real system handles.

What is real here

  • The layout, navigation and every column of the allocation table
  • The confidence bands and how they are calculated
  • The source-weighting scheme and the override behaviour
  • The allocation algorithm being described

What is invented

  • All client codes — ZULU, YANKEE, XRAY are NATO placeholders
  • All TANs — the AAAA00001A pattern is a dummy format
  • Every amount, date, count and percentage on the page
  • The deductor names, which are not companies that exist

AlgorithmAllocation is solved as an assignment problem. Within each TAN, books entries and 26AS rows are matched by minimising total cost across amount and date difference — not greedily, first-come-first-served. Above 500 rows in a single TAN it falls back to a greedy pass, because the exact solve stops being worth the time.

RankingThe deductor behind a TAN is resolved from four sources, and they disagree. A contacts upload scores 0.75, recent history in the database 0.70, older history 0.45, and the current 26AS file alone 0.35. If the candidate also appears in the file being processed it gains 0.30, capped at 0.99. A manual override is stored so that it always wins — the last row of defence when the weights get it wrong.

Reading this honestly

  • This is a reconstruction. The production interface is a React application that needs a backend, a database and live TRACES credentials to run.
  • The numbers were chosen to show the interesting states — a clean match, a rounding difference, a date gap, a rejected outlier. They are not results from a real run.
  • The tolerances, weights and the fallback threshold are as implemented. Those are the parts worth asking about.
